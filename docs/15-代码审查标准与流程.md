# 15 · 代码审查标准与流程

> 本文件为本项目定义**统一的代码审查标准与流程**，补齐「机械门禁之外」的逻辑层质量保障。
> 它**不重复**既有门禁（提交规范 §12.3、typecheck §12.9、CI §12.11、env 契约 §12.13、工程规范 §12），而是与它们**叠加成完整的质量防线**。
> 任何 AI 助手、新同事、团队成员在本仓库做变更时，都按本标准自审与被审。

---

## 15.1 为什么需要单独的审查标准

本项目已有三层**机械门禁**（自动拦截，不需要人判断）：

| 门禁 | 触发 | 检查内容 | 真相源 |
|---|---|---|---|
| 提交前钩子 | `git commit` | typecheck（shared+crawler+web）+ 单测全绿 | `scripts/precommit.mjs` |
| 提交信息 | `git commit` | Conventional Commits / 小写主题 | `.commitlintrc.json` |
| CI | push / PR | `pnpm install --frozen-lockfile` + typecheck + 单测 | `.github/workflows/ci.yml` |

**但机械门禁只保证「能编译、能跑、格式合规」，不保证「写对了、写清楚了、写得安全」。** 质量参差的典型症状：

- 解析字段全 `null` 却静默跑完（YAML regex 双反斜杠陷阱，见 §15.6）；
- 时间展示错 1000 倍（`dayjs(数字)` 当毫秒，应 `dayjs.unix()`）；
- 列表阶段没按 `canonical(detailUrl)` 先去重，库里出现重复行；
- 新依赖随手加，绕开 §12.12 的工程对比；
- 改了代码却不同步 `docs/11`、`.env.example` 或站点 YAML。

这些**只有「按标准的审查」才能拦住**。本标准就是把"老手会肉眼盯的点"变成可勾选、可交接、可复核的清单。

---

## 15.2 审查原则的定位（来自审查专家）

代码审查的目标是**提升质量 + 提升人的能力**，不是当门卫。请遵守：

1. **具体**：说清「第几行、什么现象、为什么错、怎么改」，不要只写"有安全问题"。
2. **讲原因**：不只说改成什么，要说清为什么（根因）。
3. **建议而非命令**：用「建议/考虑…因为…」，重大方向分歧回到 §12.12 与用户确认。
4. **分级**：🔴 阻断 / 🟡 建议 / 💭 优化，见 §15.3。
5. **夸好的代码**：干净的模式、巧妙的解法要指出来，强化正向行为。
6. **一次给全**：一轮审查把意见一次给完，不要分多轮 drip-feed。

---

## 15.3 严重级别定义

| 级别 | 标记 | 含义 | 合并前处理 |
|---|---|---|---|
| 阻断 | 🔴 | 正确性 / 安全 / 数据损坏 / 破坏契约 / 关键路径无错误处理 | **必须修复**，有 🔴 一律不得合并 |
| 建议 | 🟡 | 应修：缺校验、命名混淆、重要行为无测试、性能/N+1、可提取的重复 | 必须与作者达成共识；可记 follow-up，但不得带 🔴 进 main |
| 优化 | 💭 | 可选：注释缺失、次要命名、文档缝隙、更优写法 | 不阻塞，鼓励修 |

> 评判口径：**会让人半夜被告警叫醒的 = 🔴；会让后人看不懂或慢一倍的 = 🟡；纯体面的 = 💭。**

## 15.4 审查标准（按维度）

下面每一条都是本仓库的「必查项」。✅ 表示门禁已自动覆盖（无需人肉再看），🔍 表示需人工/AI 判断。

### 15.4.1 正确性（Correctness）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 写库幂等 | 🔴 | 所有写库可重复执行结果一致：种子 upsert、crawl `ON CONFLICT`、下架软删、backfill 只填空列（§12.1）。**新增写库脚本先自问"跑两遍一样吗"**。 |
| 去重口径正确 | 🔴 | 产品唯一键 `(company_id, dedupe_key, section_key)`；`dedupe_key = COALESCE(source_product_id, canonical(detail_url))`；**`sku` 绝不参与去重**（货号=产品级，同 SKU 跨栏目分两条）。列表阶段先按 `canonical(detailUrl)` 去重（`fetch/listDedupe.ts`）。 |
| 时间处理 | 🔴 | 一律 `dayjs` + `Asia/Shanghai`；**秒级必须 `dayjs.unix()`**（数据库存 Unix 秒），`dayjs(数字)` 当毫秒会错 1000 倍；展示用 `shared/time.ts` 的 `formatBj()`。 |
| 站点适配「加性」 | 🔴 | `config/sites/<domain>.yaml` 是主力；代码适配器只提供可选钩子（`preflight/preparePage/buildPageUrl/postParseList/postParseDetail`）。优先级 `YAML → 代码 Adapter → 模型兜底`；无适配器时行为须与纯 YAML **完全一致**（硬规则 5，AGENTS.md）。 |
| 字段抽取正确性 | 🟡 | FieldSpec：`number:true` 去千分位/币种后 `Number()`，失败 `null`；`$self` 读元素自身；`regex` 单反斜杠（见 §15.6 反模式）。dry-run 验证「解析条数 > 0」再合并。 |
| 形态探测/分页/栏目路由 | 🟡 | 形态 A~E 探测逻辑、SPA 双层等待（`waitForSpaSettle`：DOM 稳定且 networkidle 已发生或观察满 15s，ATCC 案例）、`pickSectionByUrl` 按 `match.*UrlIncludes` 反查栏目。非产品页（contact/about/faq/news/blog…）一律排除。 |
| 反爬/渲染分支 | 🟡 | WAF 站点（CloudFront/阿里云滑块）须自建 stealth（`--disable-blink-features=AutomationControlled` + 覆盖 `navigator.webdriver` + 真实 UA/headers）；`elabscience` 中转 `redirect:'manual'` + 带 cookie。不为 D/E 形态主动逆向接口。 |

### 15.4.2 安全性（Security）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 凭证不进库不进日志 | 🔴 | API Key / 密码只在 `.env`（被 `.gitignore` 忽略），**绝不**硬编码、绝不 `console.log` 明文。`.env.example` 只放占位。 |
| env 契约一致 | 🔴 | 代码 `process.env.XXX` 键名**必须**与根 `.env.example` 声明双向一致（静态防线 `envContract.test.ts`）。**不要把 env 读成参数**（如 `resolveConfig(env=process.env)`）绕过扫描，可测性用 `vi.stubEnv()`（§12.13）。 |
| 注入风险 | 🔴 | YAML `regex` / SQL 拼接不得混入未转义的外部输入；`better-sqlite3` 一律参数化。SQL `= NULL` 永不命中，用 `isNull()`。 |
| 跨进程 native 模块 | 🟡 | `better-sqlite3` 跨进程 require 失败时用**绝对路径** `.../better_sqlite3.node`；当前版本 **13.0.3**。 |
| 第三方请求限制 | 🟡 | 爬取请求带超时与重试上限、遵守 `robots`/频控；不把模型输出直接当你方 SQL 执行。 |

### 15.4.3 可维护性（Maintainability）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 优先复用现有包 | 🟡 | Drizzle / better-sqlite3 / cheerio / Playwright / yaml / openai / dayjs / p-limit / ExcelJS / standard-version（§12.2）。substantial 功能不重复造轮子；微型胶水（进度条、参数解析）可保留。 |
| 配置优先 | 🟡 | 站点选择器、模型参数进 `config/sites/*.yaml` 与 `config/`；逻辑放代码包；改规则优先改 YAML 不动代码。 |
| 命名与可读性 | 💭 | 复用现有命名；函数/变量自解释；跨包共享类型从 `shared` 导出。 |
| 文档一致性 | 🟡 | 改代码/配置须同步：脚本清单 `docs/11`、环境变量 `.env.example`、站点 YAML、相关设计文档（§12.4）。 |
| 不还原他人文件 | 🔴 | 提交时连同用户/他人改动一并带上；拿不准先问，禁止静默 `git checkout --`/`git restore`/`git add -A` 夹带（AGENTS 硬规则 3；曾夹带半成品事故）。 |

### 15.4.4 性能（Performance）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 并发受控 | 🟡 | 爬取并发用 `p-limit` 限制；不做无上限 `Promise.all`。 |
| 避免重复渲染/请求 | 🟡 | 同页同栏目不重复 SPA 渲染；列表→详情去重后再取；不每条详情都重开浏览器上下文。 |
| N+1 / 大对象 | 💭 | 批量 upsert 而非逐条 insert；大 HTML 不整体常驻内存过久。 |

### 15.4.5 测试（Testing）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 高价值纯逻辑有单测 | 🟡 | 与源码 co-located（`*.test.ts`，§12.10）。已锁定：FieldSpec 抽取、形态探测 A~E、`resolveSections`、`pickSectionByUrl`、URL 规范化与去重键。**新增对应逻辑须补测**。 |
| 重要行为变更有测试 | 🟡 | 改去重/解析/金额换算等核心行为，须有回归测试；无测试且影响大 → 🔴。 |
| 集成/E2E 隔离 | 💭 | 跨模块/需网络/需 fixture 的另放 `tests/e2e/`，不与秒级单测混跑。 |

### 15.4.6 一致性（Consistency）

| 检查点 | 级别 | 说明 / 本项目要点 |
|---|---|---|
| 提交规范 | ✅(门禁) | Conventional Commits；`type` 在标准枚举（无 `config`，站点配置用 `chore(sites)`）；主题不以大写词开头（中文/小写起头）。 |
| typecheck 全绿 | ✅(门禁) | `node scripts/typecheck.mjs`（shared+crawler+web）。新增 web 依赖后 `pnpm install` 自动纳入门禁。 |
| 锁文件同步 | ✅(CI) | 增删依赖后必须 `pnpm install` 并提交 `pnpm-lock.yaml`，否则 CI `--frozen-lockfile` 失败（§12.11）。 |
| 脚本单一真相源 | 🟡 | 新脚本必登记 `docs/11` + 根 `package.json` 入口；尽量单一、参数化（§12.6）。 |

## 15.5 审查流程（分层）

```
作者编码 ──▶ ① 自审清单（§15.5.1）──▶ ② pre-commit（typecheck+test，自动）
   │                                            │
   │                                       不通过 → 回改，回到①
   ▼
③ git commit（commitlint 自动）──▶ ④ push / PR ──▶ ⑤ CI（frozen-lockfile+typecheck+test，自动）
                                                        │
                                                   不通过 → 回改
                                                        ▼
                                              ⑥ 同行 / AI 审查（按 §15.4 出意见）
                                                        │
                                             有 🔴 → 必须修；🟡 达成共识
                                                        ▼
                                              ⑦ 满足 DoD（§15.5.3）→ 合并
```

### 15.5.1 ① 作者自审（提交前必做）

提交前，作者（含 AI 直跑场景）逐条过 `docs/15` 的 PR 清单（见 `.github/PULL_REQUEST_TEMPLATE.md`）。重点先排除 §15.4.1/§15.4.2 的 🔴 项。

### 15.5.2 ④ 何时需要"正式审查"

- **所有进入 `main` 的变更都需要审查**——机械门禁过 ≠ 质量过。
- **本项目执行模式特例**（用户 2026-09-24 明确：AI 全权直接执行）：AI 变更同样要过 `typecheck + test + 自审`；但以下**高影响变更必须先与用户确认再执行**（§12.12），审查意见即"与用户确认"的记录：
  - 新增依赖 / 改工具链 / 改仓库配置；
  - 改动数据口径（去重键、软删、表结构）；
  - 大范围重构 / 安全相关。
- **团队成员使用前置完成后**（M3 已交付）：团队成员提交的 PR 需至少 1 名 reviewer 通过、且无未解决的 🔴，方可合并。

### 15.5.3 ⑦ 定义完成（Definition of Done）

合并 `main` 前**必须全部满足**：

1. CI 绿（typecheck + 单测 + 锁文件一致）；
2. 审查意见无未解决 🔴；所有 🟡 已达成共识（修掉或记 follow-up）；
3. 文档/配置同步（`docs/11`、`.env.example`、站点 YAML、相关设计文档）；
4. 提交信息合规、改动按逻辑小节拆分（不攒一坨）；
5. 重要逻辑有/补了测试。

## 15.6 反模式黑名单（本项目高发，列为必查）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| YAML `regex` 用**单引号 + 双反斜杠**（`'\d'`） | 字面量不转义 → `new RegExp` 匹配字面 `\d` → 字段全 `null` → 列表 0 条静默终止 | **单反斜杠** `\d`；写入后 dry-run 验证条数 > 0 |
| `dayjs(数字)` 当秒级时间 | 展示错 1000 倍 | 秒级用 `dayjs.unix()`；统一 `formatBj()` |
| `sku` 参与去重键 | 同 SKU 跨栏目被当重复、数据丢失 | 去重键只用 `(company_id, dedupe_key, section_key)`，`sku` 排除 |
| 列表阶段未先 `canonical(detailUrl)` 去重 | 库内重复行 | 落库前 `fetch/listDedupe.ts` 先去重 |
| SPA 只等 `networkidle` | 埋点长轮询永不触发 → 拿空壳 | 用 `waitForSpaSettle`（双层条件） |
| env 键名与 `.env.example` 不一致 | 调用时才暴露，报错指不到根因 | 双向静态校验 `envContract.test.ts`；不把 env 包成参数绕过 |
| SSR 站用含 `Bot` 的默认 UA | 列表被剥返回空壳 → 0 条 | 默认 UA 像浏览器（DEFAULT_UA） |
| `git add -A` / 静默 `git restore` | 夹带他人半成品 / 丢用户改动 | 具体 `git add <文件>`；绝不还原他人文件 |
| 机械门禁过了就合并 | 逻辑错误/安全遗漏漏网 | 必过 §15.4 审查标准 |

## 15.7 审查意见格式（模板）

```
🔴 【正确性：去重口径】  packages/crawler/src/ingest/upsert.ts:42
dedupe_key 误把 sku 拼进去了，同 SKU 跨栏目会被当重复丢弃。

为什么：货号是产品级，跨栏目应分两条（见 docs/15 §15.4.1）。
建议：改为 COALESCE(source_product_id, canonical(detail_url))，sku 仅留作展示列。

🟡 【可维护性：缺测试】 packages/crawler/src/config/resolveSections.ts
新增的 match.urlIncludes 反查逻辑没有单测。

💭 【优化】 packages/shared/src/time.ts:10
这处注释可以说明时区无关的存储约定，方便后人。
```

## 15.8 记录与追溯

- 审查意见留在 PR 评论；重大设计分歧/方向决策走 `docs/decisions/ADR-xxx.md`（含背景/决策/理由/后果）。
- 新发现的"坑"沉淀进 `docs/12-工程规范.md`（通用纪律）或 `docs/14-站点接入问题清单.md`（站点级台账），避免重复踩。
- 本文件随项目演进**持续补充**：标准有缺口、反模式又出现新物种，当轮就更新此处。

## 15.9 与既有门禁的关系（一句话）

> 机械门禁（pre-commit / CI / commitlint）保证"编译过、跑得动、格式对"；**本标准保证"写对了、写清了、写得安全"**——两者缺一不可，共同构成本项目的质量防线。
