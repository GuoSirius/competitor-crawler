# 07 · 告警与规则自愈

> 本篇回答"**什么时候该叫人、叫多急、叫完之后怎么修**"。告警是系统的"免疫系统"——它区分"官网真更新"与"规则该改"，并保证凡需人工介入必被看见（human-in-the-loop）。

## 7.1 业务视角：告警要解决的痛点

- 字段突变可能是**官网改版**（需改提取规则），也可能是**产品真更新**（正常业务）。混为一谈会淹没人工。
- 国外站不可达、翻页接口定位不到——这些**必须人工协助**（开 VPN / 补接口），不能静默跳过。
- 告警要"高信噪比"：能自动判定的自动处理，只剩真正要人看的才上报告警。

## 7.2 告警类型

| 类型 | 触发条件 | 严重度 | 处理方 |
|---|---|---|---|
| `MISSING_FIELD` | 某产品本应有字段（历史有、schema 要求）本次提取为空 | warning | 先模型归因 → 人工复核 |
| `FIELD_CHANGED` | 字段值相对上次快照变化（如价格/克隆号） | info/warning | 自动记录，按幅度定级 |
| `BULK_DRIFT` | 某站 ≥30% 产品同字段突变（疑似改版） | error | 规则待修订 |
| `SITE_UNREACHABLE` | 域名不可达（含 GFW 限制） | error | 人工开 VPN / 代理 |
| `NEEDS_API_HINT` | 翻页接口定位不到 / 列表遍历失败 | warning | 人工补接口或切 UI 模式 |
| `MODEL_FAILURE` | 模型校验失败且重试后仍失败 | warning | 降级 selector / 标记缺失 |

## 7.3 分级与路由

```
severity:
  info     → 记入 crawls.summary，不主动推送（报表可见）
  warning  → 推送至 企微/钉钉 机器人（日常工作群）
  error    → 推送 + 邮件，并置 alerts.status=open 等待 ack
```

- 每个告警都落 `alerts` 表（带 `payload` 结构细节：旧值/新值/样本 URL），可追溯、可复盘。
- `BULK_DRIFT` 与 `SITE_UNREACHABLE` 默认 error 级，必须有人 ack。

## 7.4 变化归因：区分"真更新" vs "规则该改"

> 这是告警信噪比的关键，由模型辅助层（04）完成。

```
某产品字段变化
   │
   ▼ 模型 attribution 任务
{ kind: 'real_update' | 'structural_change' | 'extraction_error', confidence, reason }
   │
   ├─ real_update        → 记 FIELD_CHANGED(info)，正常入库
   ├─ structural_change  → 记 BULK_DRIFT(error)，建议"改该站适配器/YAML"
   └─ extraction_error   → 记 MISSING_FIELD(warning)，建议"复核选择器/换模型模式"
```

- 低置信度一律归 `extraction_error`，**不武断判定**，避免误报"官网改版"。
- 阈值可配：`BULK_DRIFT` 比例（默认 30%）、`FIELD_CHANGED` 价格变动幅度（如 >20% 才 warning）。

## 7.5 规则修订闭环（自愈）

```
收到 error 级告警（BULK_DRIFT / NEEDS_API_HINT / MISSING_FIELD）
   │
   ▼
1. 人工查看 alerts.payload（样本 URL + 旧/新快照）
2. 判定根因：
   a. 选择器失效     → 改 config/sites/<domain>.yaml 的 selectors（零代码）
   b. 结构大改       → 写/改 代码 Adapter，或切 model-generic 兜底
   c. 翻页接口变了   → 你找到新接口回填，或设 fallbackToUi=true 走 UI 驱动
   d. 国外站不可达   → 开 VPN / 配代理，重跑 pnpm crawl --site <domain>
3. 修复后跑 dry-run 验证该站字段恢复
4. 重新 crawl，确认告警消失 → alerts.status = resolved（或 auto_fixed）
5. 若改了规则，提交并推送到仓库（见 git 约定）
```

- **自愈边界**：系统能自动做的是"模型兜底、重试、降级、回退 UI"；涉及"改版需改规则"的，**必须人工确认后改配置**——不擅自改写核心逻辑。
- 所有修复都走配置优先，保证"改规则不动代码"（见 02 设计原则 ①）。

## 7.6 推送通道

- 即时：企微 / 钉钉 机器人 webhook（warning/error 级）。
- 邮件：163 / 企业邮（error 级 + 日报摘要）。
- 可扩展：Server酱 / PushPlus（参考你 A 股流水线的通知链路）。
- 配置放 `.env`（`ALERT_WEBHOOK_URL` / `ALERT_EMAIL_*`），通道增删不动业务代码。

## 7.7 告警质量目标

- **不漏**：凡需人工介入的必告警（不可达、接口定位不到、批量突变）。
- **不噪**：能自动归因/降级的，不上升到 error；低置信度宁归 extraction_error。
- **可追溯**：每条告警带样本与快照，复盘时一眼看懂发生了什么。
