# ADR-002 · 模型部署方式

- 状态：已采纳（Accepted）
- 日期：2026-09-23
- 决策人：郭之存（系统开发组）

## 背景

模型贯穿 ③提取 / ⑤归一化 / ⑥变化归因 / ⑦告警 四环节，是处理"千站千面"的关键。用户明确表示：
- 可接受**本机轻量模型**或**云端大模型**辅助，不局限于纯代码；
- 希望支持**三种模式**——纯本地、纯云端、混合（本地+云端）——且**通过配置切换**；
- 模型必须有**明确提示词约束**，否则会不一致甚至臆造。

## 决策

统一经 **OpenAI 兼容客户端**调用，支持 `MODEL_MODE = local | cloud | hybrid`：
- `local`：仅本地（Ollama/vLLM，如 `qwen2.5:14b-instruct` / `qwen2.5-vl:7b`）。
- `cloud`：仅云端（通义/DashScope、DeepSeek、Claude）。
- `hybrid`（默认）：本地优先，本地失败/超时自动回退云端。

并强制**防幻觉四件套**：强约束提示词 + Zod 校验 + temperature=0 + 失败重试一次；缺失字段为 `null`，绝不编造。

## 理由

1. **三种模式纯配置**：`.env` 与 `config/model.yaml` 二选一，业务代码不感知模式，满足"我要能切换"的硬要求。
2. **混合模式兼顾隐私与可用**：内网/无外网走本地（数据不出本机）；本地挂了自动云端兜底，单点不阻塞整轮。
3. **视觉模型适配用户要求**：`qwen2.5-vl` 直接读 Playwright 截图，天然落地"优先浏览器渲染、不逆向接口"。
4. **确定性可追溯**：temperature=0 + Zod 让提取结果可复现，告警/归因可审计，避免模型"每次不一样"。
5. **不臆造**：提示词红线 + null 兜底 + 重试失败降级（selector/告警），脏数据绝不入库。

## 后果

- 正面：部署灵活、可演进（加新模型只改配置）；低噪声；失败有降级路径。
- 代价：本地需自备 GPU/算力跑 14B 模型；云端有 API 成本与配额管理。
- 风险：模型失败仍需人工兜底（selector / 改 YAML）；已通过告警分级（07）兜住。
- 配置：`MODEL_TEMPERATURE=0`、`MODEL_MAX_RETRIES=1`，任务级可覆写（见 04）。
