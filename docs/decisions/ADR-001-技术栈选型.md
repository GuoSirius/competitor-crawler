# ADR-001 · 技术栈选型

- 状态：已采纳（Accepted）
- 日期：2026-09-23
- 决策人：郭之存（系统开发组）

## 背景

竞品爬虫是**长期维护**项目：24 站点、上百品类、异构页面，需季度增量、软删除、模型辅助、下游分析，并计划后期从 SQLite 切到 MySQL/PG。早期曾考虑 Python（用户现有视频流水线用 Python/Anaconda）与 Node+SQLAlchemy 路线，但用户是前端开发者、对 Node.js 极熟，且本项目无 Python 独占需求。

## 决策

采用 **Node.js + TypeScript (ESM) + pnpm workspace (monorepo)**，持久层用 **Drizzle ORM**，抓取用 **Playwright + undici/cheerio**，模型用 **OpenAI 兼容客户端（本地 Ollama/vLLM + 云端通义/DeepSeek/Claude 兜底）**，下游用 **ExcelJS / ECharts / Nuxt 3**。

## 理由

1. **团队契合**：用户是 Node/前端专家，TS 类型系统可在编译期约束"统一产品结构"，减少异构解析的运行时错误。
2. **无感切库**：Drizzle 跨方言（SQLite/MySQL/PG）同一份 schema，满足"后期切生产库不动业务代码"。
3. **抓取能力**：Playwright 无头浏览器天然解决 JS 渲染/加密/风控站的"用户所见即所得"提取，且可按用户要求优先 UI 驱动、不逆向接口。
4. **模型互通**：OpenAI 兼容接口同时适配本地与云端模型，三种部署模式纯配置切换。
5. **下游连贯**：Nuxt 3 + Vue 3 + UnoCSS 贴合用户既有技术栈（elabcn-nuxt、三态页头组件），应用页开发零切换成本。

## 后果

- 正面：单语言栈（TS）贯穿爬虫/模型/下游；类型安全；切库/切模型均配置化。
- 负面/代价：放弃 Python 复用（但本项目无 Python 强需求）；需维护 pnpm monorepo 结构（已规划 `packages/shared|crawler|web`）。
- 风险：Node 端重型 HTML 解析生态略逊 Python，但 Playwright + cheerio 已覆盖需求。
- 遵循：用户"先文档后代码、目录先规划好"的要求，本文档与 02/03 配套，代码阶段再落地。
