## 方法论（本次复探统一遵循）

1. **导航 PRODUCTS 下拉是找列表的通用入口**：斯达特真实列表在跨域 `ua-bio.com/goodsList`、金斯瑞进 `*-products.html`、近岸进 `/product-list?id=N`、同立海源进 `mAb.html`、R&D 进 `/products/*`。
2. **遍历 PRODUCTS 下拉时必须排除非产品页**：`contact / about / 公司简介 / faq / news / blog / support / download / career / search / cart / login / privacy / terms` 等一律跳过，只取品类/产品类链接。
3. **stealth 已上线**：`fetch/page.ts` 的 `spaFetch` 现带 stealth（`--disable-blink-features=AutomationControlled` + 覆盖 `navigator.webdriver` + 真实 UA/headers），可过 CloudFront/阿里云滑块等 WAF；`pnpm probe/crawl -- --site <d> --render spa` 触发。
4. **配置真相源是 `config/sites/<domain>.yaml`**，能 SSR 抓的优先不挂 render；必须 SPA 的显式 `--render spa`。整站统一模式写顶层 `render`；列表/详情不一致的 Hybrid 站写 `renderList` / `renderDetail`（回退链 renderList → render → 顶层 render → auto，见 10.3）。

## 机制速查图（接入前先看）

- ![startUrl/startUrls 入口继承与翻页机制](assets/entry-paginate-flow.svg)——`startUrl`（顶层字符串）与 `startUrls`（栏目数组）是**继承回退**关系；数组语义 = **全部逐个抓取**（不是优先取一个），每个入口各自跑完整翻页；`pagination-url` 的 `urlTemplate` 以**当前入口**为 base 拼页码（完整 URL 模板与入口无关，多入口会重复翻同一序列）。
- ![match 反查路由机制](assets/match-routing.svg)——`listUrlIncludes` / `detailUrlIncludes` **不是抓取入口**，是「拿到没打 sectionKey 的 URL」时的反查路由器（`pickSectionByUrl`）：数组内 OR 匹配、section 间按声明顺序取第一个；当前生产代码零调用（主流程列表阶段已打 sectionKey），为 resume/钩子场景预留。
