## 4.1 「说我被拦、用户说能开」的三处真 bug（2026-10-05 修，勿回退）

| # | bug | 现象 | 现状 |
|---|---|---|---|
| 1 | `isAutoPassableChallenge` 只按**文案**判自动放行 | 命中 `cf-mitigated: challenge` 响应头时 `matched` 不含文案 → 判「不可自动放行」→ **重试循环整段被跳过**，托管挑战一刀切判死 | 已修（头 + 文案两路都认）+ 5 例回归 |
| 2 | `assessChallenge` 状态码分支用 `HTTP 403` 覆盖 `matched` | 已判明的文案信号（`Just a moment...`）被抹成无信息量状态码，上层据此误判 | 已修（优先带真实命中特征，无信号才回退状态码） |
| 3 | `stealthInitSource` 把硬件特征**硬编码**成 8 核 / 8G、plugins 造 4 个、mimeTypes 造 4 个 `application/pdf` | 反检测脚本自己造破绽：真实 Chrome 是 16 核 / plugins 5 / mimeTypes 2（`application/pdf` + `text/pdf`），数量与内容双不自洽 | 已改为**只补缺不篡改**（内核有真值一律不碰；`plugins`/`mimeTypes` 仅在读出来是空时才造，且按真值配对）。验收工具 = `pnpm diagnose` 的指纹体检 |


## 5. 挑战检测 SOP（`fetch/challenge.ts`，防误报防漏报）

> 原则：**判定只在 fetchPage 内做一次**（`assessChallenge`），上层（sweep/validate）禁止用旧正则重复分类。

| 信号层 | 内容 | 判定 |
|---|---|---|
| ① 响应头 | `cf-mitigated` / `x-px-*` / incapsula，逐条 key+value 匹配 | high |
| ② 特异文案 | innerText 可见文本含 just a moment / request unsuccessful / 滑动验证等 | high |
| ③ 宽泛文案 | unusual traffic / security check / perimeterx（正常页也可能有） | 需 domWidget 或「无内容」佐证 |
| ④ 状态码 | 403/405/406/412/429/451/503 | high（优先于软拦） |
| ⑤ 反向放行 | 中/弱信号 + 正文 ≥500 字符 + 无验证控件 | falseAlarm（正常页） |
| ⑥ 软拦 | <200 字符空壳 | suspicious |

关键实现：browser 通道用 `innerText` + 响应头 + DOM 控件查询（`#rc-anchor`/`iframe[src*="recaptcha/anchor"]`/`#px-captcha`/turnstile 等）。**innerText 优先**——Promega 把 `.g-recaptcha` 写进富文本白名单 JSON，裸匹配 HTML 必误报。

> **2026-10-02 修复（challenge.ts）**：ssr 通道只有整页 HTML，原先 `htmlHit = SPECIFIC ∪ BROAD` 把站点自有的 `class="g-recaptcha"` 当中等挑战直接 `throw ChallengeError`（ScienCell 实测踩中，正常产品页被判 captcha）。现两条通道分层一致：特异文案 specific → 宽泛 broad → 中文边角 medium 逐级降级，且
> ① ssr 命中**特异文案时也只降 medium**（整页 HTML 里它可能是脚本/白名单 JSON，不是可见挑战）；
> ② 宽泛词（g-recaptcha / unusual traffic）**命中但有实质内容（≥500 字 + 无验证控件）→ 判 `confidence:'none'` 放行**，与 browser 通道「误报放行」对齐；
> ③ 无 innerText 时才退回 HTML 层判定。单测补了 ssr 通道 2 例（不误检 / 特异降级），合计 16 例。

## 5.5 代理口径（2026-10-04 · 用户口径：**YAML 是唯一裁决方**）

> **根因**：Chromium **不认** `http_proxy` / `HTTPS_PROXY` 环境变量（只读 Windows 系统代理设置），Node 的 fetch 也不认。开了 VPN 若不显式配置，抓取仍以**本机 IP** 直连。

| 规则 | 说明 |
|---|---|
| **配了就走、没配就直连** | 唯一开关是站点/栏目 YAML 的 `proxy:`。**代码层没有任何域名/地区黑名单** |
| **按站/栏目开代理** | YAML 顶层 `proxy: '${CRAWL_PROXY}'`（推荐，端口只在 .env 维护一处）或写完整 URL；section 级可单独覆盖 |
| **双通道生效** | browser 走 `newContext({proxy})`；ssr 因 Node fetch 无代理能力，改用 Playwright 的 `APIRequestContext`（`ssrFetchViaProxy`，按需创建、复用浏览器实例） |

> **2026-10-04 变更（用户要求）**：早期版本在 `page.ts` 里写了 `resolveProxy()`，对 `.cn` 域名**硬忽略代理**。
> 用户明确要求移除——「不需要走代理的就不走，**由 YAML 控制**，不要在代码里写死」（见 §7 纪律）。
> 现已删除该规则：`.cn` 站只要在 YAML 里配了 `proxy` 就会走代理，没配就直连。
> 伊莱瑞特中文站因此**不在 YAML 写 proxy**（实测直连 403 风险警告页、走代理同样 403——该 WAF 是地域策略），属配置决策而非代码强制。

配置写法见 `config/sites/_template.yaml` §1.1 与 `.env.example` 的 `CRAWL_PROXY`（填**完整 URL**，不是只填端口）。

## 7. 配置效率经验（YAML 坑速查）

- **YAML 正则一律单引号风格**：双引号串 `\d` 是非法转义（Invalid escape sequence）；内嵌单引号写 `''`。
- **cheerio 定位含变量的 script**：`sel: 'script:contains(priceStr)'`（取第一个 `script` 常命中无变量节点）。
- **`:has()` 在当前 cheerio 不可用**；emotion/styled hash 类名带语义后缀（`-productNumber`/`-tBodyRow`）可用 `[class*="语义"]` 稳定匹配。
- **aspx 证书链不全的站必须 `render: browser`**（ssr 握手失败；playwright ignoreHTTPSErrors 可过）。
- **批量配置流水线**：批量抓 HTML → python 分析（href 模式聚类 + 容器 class 出现次数 ≥8）→ 手写 YAML → probe。gen-site 模型兜底对 >500KB 大前端渲染页常报 NEED_MORE_HTML，不可靠。
- **三种产品入口口径**（用户定义）：① 无列表页 → 导航找落地页、落地页进列表页，startUrls 写最终列表页；② 有直接列表页 → 即入口；③ 只有搜索框 → 宽泛关键词搜全量列表当入口。
- **多表/多卡布局不统一的站，先找「形态一致」的统一入口，别逐个分类写 itemSelector**：procellsystem 的 `/products/<slug>` 落地页三类布局混用（`table.zhongdian-pro`、`table.table`、卡片 `div.other-list`），还有 2 个空分类；改用 `/search-category=<top>`（统一 `div.pro_item` + `?page=N`）后一次配全 14 栏目。fn-test 同理：`/elisa-kits/` 的 `div.reference-card` 是**文献卡**，真列表在 `product-cat/<cat>` 归档页。
- **站点特有字段名会被 validate 判拼写告警**：`chineseName`/`cnName`/`chineseTitle` 距内建字段 ≤1 → `UNKNOWN_FIELD_TYPO` warn（10 栏目刷 10 条）。中文名这类字段宁可不配，靠详情阶段 `captureRest` 兜底进 row。列表侧不同源的同义字段（如 procellsystem 的 Cat.No. vs 详情货号）改名成 `catNo` 之类不撞内建的写法，才可避免两阶段字段不一致告警。

### 翻页两大类（用户最终口径，引擎/文档统一按此表述）

| 两大类 | 形态 | 引擎实现 | 配置写法 | 现网实例 |
|---|---|---|---|---|
| **① SSR 直出列表翻页** | 服务端渲染好整页 HTML，翻页 = 换 URL（每页固定条数） | `strategy: pagination-url`（`urlTemplate` 含 `{page}`）或 `pagination-html`（取页面上「下一页」链接） | 见右列 | cusabio `catalog-30-{page}.html`、富衡 `col.jsp?m426pageno={page}`、procellsystem `?page={page}`、fn-test `link[rel=next]`、beyotime 单页全量不翻 |
| **② CSR 接口渲染** | 页面主体由接口数据在浏览器拼出来 | ②-a **点击分页 / 加载更多**：`pagination-html` + `nextSelector`，或 URL 带可直连页码时用 `pagination-url`；②-b **滚动加载**（到底自动追加）：`strategy: scroll-api` | 接口站还要配 `waitSelector`（列表容器**内容级**选择器，超时接 `listRetry`）；`CRAWL_BROWSER_MAX_WAIT` 单位毫秒 | bioxcell（Algolia instant search，点 Load more 累积，URL 页码同步递增且刷新只出本页）、bioassaysys `page/{page}/` |

> 口径补充：没有第 4 条路径——`strategy: none` 只是「单页兜底」声明（listOnly 栏目继承到站点级 URL 翻页模板时必须显式关停，否则每页都返回全量 → 白翻到 maxPages 上限）。
> 判定口诀：**看换页时URL 变不变 + 不变时内容由谁拼**。SSR 类换 URL 整页直出；CSR 类 URL 可变（如 bioxcell `?page=N` 真分页）也可不变（滚动加载），但真数据都来自接口。
