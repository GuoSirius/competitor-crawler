# 06 · 运行与调度

> 本篇回答"**怎么跑起来、怎么定期跑、国外站爬不了怎么办**"。面向系统开发组（你）的运维手册。

## 6.1 业务视角：运行节奏

- **种子维护**：竞品清单 Excel 更新时，跑一次 `seed` 把变更同步进库（增量，不会清空历史）。
- **季度全量增量**：由 Scheduler 在每季度触发；也可手动 `crawl` 单跑/补跑。
- **国外站协作**：遇到 GFW 不可达的站点，系统**主动告警**，你开 VPN 后重跑该站（不阻塞其他站）。

## 6.2 安装（首次）

> 用户约定：安装与启动由你自己执行，AI 不代劳。以下给出确切命令供你执行。

```bash
# 1. 安装依赖（monorepo，根目录一次装全）
pnpm install

# 2. 安装 Playwright 浏览器内核（用封装好的 pnpm playwright:install）
pnpm playwright:install

# 3. 准备本地库（SQLite 默认，无需额外服务）
cp .env.example .env
#   按需改 .env：DB_DIALECT=sqlite，MODEL_MODE=hybrid

# 4. 初始化数据库表结构（Drizzle push）
pnpm --filter @competitor-crawler/shared db:push
```

## 6.3 命令一览（根 package.json scripts）

| 命令 | 作用 | 备注 |
|---|---|---|
| `pnpm seed` | 执行 `scripts/xlsx-to-seeds` + Seed Loader 增量同步 | Excel 更新后跑 |
| `pnpm crawl` | 跑全量增量爬取（按 seeds + 适配器） | 季度主任务 |
| `pnpm crawl --site <domain>` | 仅爬指定站点 | 调试 / 单站补跑 |
| `pnpm crawl --dry-run --pages 2` | 只爬前 2 页、不入库 | 接站点前验证 |
| `pnpm typecheck` / `pnpm build` | 类型检查 / 构建 | CI 与提交前 |
| `pnpm report` | 生成下游交付物（见 08） | 导出/图表/应用页 |

## 6.4 季度调度

```ts
// packages/crawler/src/scheduler.ts（伪代码）
import { CronJob } from 'cron';

// 每季度首月 1 日 03:00 触发
new CronJob('0 0 3 1 1,4,7,10 *', () => {
  runCrawl({ trigger: 'schedule' })
    .then(summary => notify(summary))
    .catch(err => alert({ type: 'SITE_UNREACHABLE', message: String(err) }));
});
```

- 触发后写入 `crawls` 批次（status=running → success/partial/failed）。
- 结束后推送本轮 `summary`（新增/更新/下架/告警数）到告警通道（见 07）。
- 也可挂到系统级定时（Windows 任务计划 / cron），本质是调 `pnpm crawl`。

## 6.5 国外站点不可达：主动告警 + VPN 协作

部分站点（如部分海外厂商）在**中国大陆网络**下无法直接访问。处理流程：

```
Fetch 层对某域名发起请求：
  连续 N 次连接超时 / TLS 重置 / 403 来自 GFW 特征
     → 判定 SITE_UNREACHABLE（severity=error）
     → 该站点本轮标记 skipped，不影响其他站点
     → 告警文案明确："域名 X 疑似被网络限制，请开启 VPN 后重新运行 pnpm crawl --site X"
```

- **不静默失败**：一定发告警，让你决定开 VPN。
- **单站补跑**：你开好 VPN 后，`pnpm crawl --site <domain>` 单独补，结果并入同一/新批次。
- **长期方案**：若某站长期需代理，可在 `config/sites/<domain>.yaml` 增加 `proxy: required` 标记，Fetch 层自动走代理配置（仍需你提供可用代理）。

## 6.6 运行可观测

- 每轮 `crawls.summary` 记录：处理公司数 / 品类数 / 新增 / 更新 / 下架 / 告警数 / 模型调用与回退数。
- 日志分级：INFO（进度）/ WARN（单页失败重试）/ ERROR（站点级失败）。
- 失败隔离：单页/单站失败不影响整轮，整轮以 `partial` 收尾并告警，绝不"全有或全无"。

## 6.7 资源与限速

- 默认限速：每域名请求间隔、并发页数受控，避免被封（视站点风控调 `config/sites/*.yaml` 的 `rateLimit`）。
- 本地模型：首次需先拉起 Ollama/vLLM 服务（`ollama pull qwen2.5:14b-instruct` 等），详见 04.2.1。
- 云端模型：注意 API key 与配额，异常高失败率本身触发告警。
