# 10 · 验证与配置生成工具

> 本篇回答"**新增/调整站点时，怎么低成本验证 YAML 是否正确、怎么快速生成配置、怎么把重要字段晋升成列**"。对应代码：`packages/crawler/src/commands/*` 的 `probe` / `gen-site` / `gen-site-template` / `gen-site-batch` / `backfill` 五个命令。

## 10.1 设计原则

- **先验证、后批量**：任何站点 YAML / 适配器改动，必须先用 `probe` 单站抽样确认能正确解析，再纳入正式 `crawl` 批次，避免整轮失败或脏数据入库。
- **模型兜底生成配置**：给列表页（及可选详情页）地址，脚本抓取页面 → 调模型（temp=0）→ 产出 `config/sites/<domain>.yaml`，你只需微调验证。
- **字段晋升可回填**：`row` 兜底存储后，若某字段变重要，新建列并回填历史数据，过程统一、幂等。
- **两套配置模板**：单规则用 `config/sites/_template.yaml`；一域名多套规则用 `config/sites/_template.sections.yaml`（见 05.3.2）。

## 10.2 probe · 单站验证

加载 `config/sites/<domain>.yaml`，抓取列表页并跑解析，打印抽取条数与前 N 条样本。

```bash
# 单规则站点（无 sections，等价于只有一个 default 栏目）
pnpm probe --domain abcam.com --list-url "https://www.abcam.com/primary-antibodies" --render auto --sample 5

# 多规则站点：逐栏目验证；也可只验证某个栏目
pnpm probe --domain example.com
pnpm probe --domain example.com --section promo
```

| 参数 | 必需 | 说明 |
|---|---|---|
| `--domain` | 是 | 站点域名，对应 `config/sites/<domain>.yaml` |
| `--list-url` | 否* | 列表页地址；缺省时取该栏目的 `startUrls`（单规则取 YAML 的 `startUrl`） |
| `--render` | 否 | `ssr` / `browser` / `auto`（默认 `auto`：ssr 内容过少自动回退 Playwright） |
| `--sample` | 否 | 每栏目打印前 N 条样本（默认 5） |
| `--section` | 否 | 仅验证指定栏目（多规则站点）；省略则遍历全部 section |

> *若 YAML 里已写 `startUrl` / `startUrls`，可只传 `--domain`。

校验要点：
- 解析出 0 条 → 检查 `parseList.itemSelector` 与 `fields` 选择器是否匹配页面结构。
- 部分条目缺 `detailUrl` → 检查 `parseList.fields.detailUrl` 的 `sel`/`attr` 是否取到链接。
- 多规则站点：样本会带 `[sectionKey]` 前缀，逐栏目核对，确认每个 section 命中各自规则（去重口径 B 生效的前提）。
- 进度单行刷新（stderr），不污染 stdout，便于脚本解析。

> **配置不完整（桩）不会崩溃**：对只写了 `domain/company/role/currency` 等身份字段的 YAML 桩直接跑 `probe`，会打印**友好告警并正常退出（exit 0，无 pnpm 报错横幅）**，提示先执行 `pnpm gen-site` 补全解析规则——这是预期工作流分支（先 gen-site 再 probe），不是错误。

## 10.3 gen-site · 模型驱动生成配置

给站点信息，脚本自动产出可用 YAML。

```bash
pnpm gen-site \
  --domain abcam.com \
  --list-url "https://www.abcam.com/primary-antibodies" \
  --detail-url "https://www.abcam.com/product/xxx" \
  --company-key "Abcam" \
  --competitor-type "抗体" \
  --role competitor \
  --currency CNY \
  --render auto \
  --notes "列表为分页结构，每页 20 条"
```

| 参数 | 必需 | 说明 |
|---|---|---|
| `--domain` | 是 | 域名，决定产出文件名 `config/sites/<domain>.yaml` |
| `--list-url` | 否* | 列表页地址（抓取入口）。**已存在的 YAML 桩写有 `startUrl` 时可省略**（自动复用；CLI 传入优先），二者都没有则报错 |
| `--detail-url` | 否 | 详情页地址，提供更完整字段抽取样本 |
| `--company-key` | 否 | 归属公司名，写入 YAML 的 `company`（同名=同一家公司） |
| `--competitor-type` | 否 | 竞品类型，写入 YAML 的 `competitorType` → companies.competitor_type |
| `--role` | 否 | 公司角色 `own`（我方）/ `competitor`（竞品），写入 YAML 的 `role` |
| `--currency` | 否 | 币种，写入 YAML 的 `currency`（缺省 `CNY`） |
| `--render` | 否 | `ssr/browser/auto`，默认 `auto` |
| `--notes` | 否 | 补充说明（页面结构、分页方式等），帮助模型更准 |

产出后脚本会提示下一步：`pnpm probe --domain <domain> --list-url <url>` 验证。

> **产出回验闭环（2026-09-30）**：模型产出后，脚本自动把选择器放回**真实抓取的 HTML** 上验证：
> - **hard 违规**（pagination-url 缺 urlTemplate / 列表解析 0 条）→ 携带违规说明打回模型重试（最多 2 轮）；重试耗尽仍不过 → **拒写盘**并给出违规清单；
> - **soft 违规**（详情页字段未命中）→ 接受产出，但文件头写 `# ⚠️ TODO` 注释列出未命中字段 + 控制台提醒。
>
> 因此 gen-site 的定位是**草稿生成器**：回验全通过 ≈ 可用；带 TODO 仍需按 probe 流程人工确认。标准流程永远是 `gen-site → probe --sample 3 --detail 2 → 修正`。

> 模型调用走 `MODEL_MODE`（local/cloud/hybrid，temp=0）；本地需先起 Ollama/vLLM（见 04.2.1）。

> **安全合并**：若 `config/sites/<domain>.yaml` 已存在（如你已手写 `company`/`role`/`currency`），`gen-site` 只让模型产出覆盖**解析相关字段**，身份字段按「CLI 传入 > **已存在文件（用户手填即真相）** > 模型产出」兜底——模型值只作全新站点（无既有文件）时的兜底，绝不会覆盖你手填的身份信息（背景：普诺赛桩里 `company: 普诺赛中文站` 曾被模型产出的 `Procell` 覆盖，已修复并有回归单测）。所以「先手写身份字段、再跑 gen-site 补解析规则」是受支持的姿势。

> **渲染模式写入 YAML**：`render`（ssr/browser/auto）现在会持久化进 `config/sites/<domain>.yaml`，并供 `probe` / `crawl` 统一复用（`--render` 仍可临时覆盖）。批量站点混合 ssr/browser 时，逐站把 `render` 写在自己的 YAML（或批量表对应列）即可，无需每次手动指定；纯 CSR 站用 `auto`（先静态抓、内容过少自动升级 Playwright）或显式 `browser`。
>
> **Hybrid 站点（渲染模式不一致）**：同一站内不同栏目、或列表页与详情页用不同模式时，可分别指定 `renderList`（仅列表页）/ `renderDetail`（仅详情页）——写在 YAML 顶层（单规则站点）或对应 section 内（多规则站点）均可。回退链：列表 = `renderList` → `render` → 顶层 `render` → `auto`；详情 = `renderDetail` → `render` → 顶层 `render` → `auto`。典型场景：产品列表 SSR、新闻列表 CSR（各 section 分别写 `render: ssr` / `render: browser`）；或列表页 SSR、详情页 CSR（`renderList: ssr` + `renderDetail: browser`）。

## 10.4 gen-site:template · 批量生成 Excel 模板

批量新增站点时，先产出**标准填报表**，填好后交给 `gen-site:batch` 一次性生成（替代逐个 `gen-site`）。

```bash
# 默认落 data/seeds/gen-site-template.xlsx
pnpm gen-site:template
# 自定义输出路径
pnpm gen-site:template --file data/seeds/2026Q4-新站点.xlsx
```

| 参数 | 必需 | 说明 |
|---|---|---|
| `--file` | 否 | 输出路径；缺省 `data/seeds/gen-site-template.xlsx`（目录不存在会自动创建） |

产出的工作簿含两个 sheet：

- **「站点清单」**：表头 + 1 行灰色示例（正式使用前请整行删除）。列如下：

| 列 | 必填 | 说明 |
|---|---|---|
| `域名(domain)` | 是 | 决定产出文件名 `config/sites/<domain>.yaml` |
| `列表页URL(listUrl)` | 是 | 列表页地址，模型据此生成 `parseList` |
| `详情页URL(detailUrl,可选)` | 否 | 提供后模型同时参考详情模板，生成更准；且会尝试识别面包屑产出 `categoryFromPage`（动态分类） |
| `公司(companyKey,可选)` | 否 | 写入 YAML 的 `company`（同名=同一家公司，多域名共用同一名字）；不填则爬取时按域名兜底 |
| `竞品类型(competitorType,可选)` | 否 | 写入 YAML 的 `competitorType` → companies.competitor_type，供筛选/分组 |
| `角色(role,可选:own/competitor)` | 否 | 写入 YAML 的 `role` → companies.role（own=我方 / competitor=竞品，缺省 competitor） |
| `币种(currency,可选)` | 否 | 写入 YAML 的 `currency` → products.currency，缺省 `CNY`；国际站填 `USD`，中文站可填 `元`/`CNY` |
| `渲染(render,可选:ssr/browser/auto)` | 否 | 渲染模式，缺省 `auto` |
| `备注(notes,可选)` | 否 | 页面结构 / 特殊翻页等补充说明，帮助模型 |

- **「填写说明」**：上表逐列含义 + 使用步骤，随文件分发，避免口头交接。

## 10.5 gen-site:batch · 批量生成站点配置

读批量表 → **逐行**调用 `genSite` → 产出 `config/sites/<domain>.yaml`。**失败隔离**：单行失败只计失败并继续，末尾汇总「成功 / 失败 / 共 N」。

```bash
# 默认读 data/seeds/gen-site-template.xlsx（与模板同一文件：生成 → 填好 → 直接跑，无需改名）
pnpm gen-site:batch
# 指定其它表
pnpm gen-site:batch --file data/seeds/2026Q4-新站点.xlsx
# 仅解析并打印待生成清单，不调模型、不落盘
pnpm gen-site:batch --dry-run
```

| 参数 | 必需 | 说明 |
|---|---|---|
| `--file` | 否 | 批量表路径；缺省 `data/seeds/gen-site-template.xlsx`（与模板输出同文件，填完即跑） |
| `--dry-run` | 否 | 只解析并打印 `第N行 → domain / listUrl / …`，**不调模型、不写 YAML** |

- **列识别按表头关键字**（大小写不敏感、包含匹配），不依赖列顺序：`domain`/`域名`、`listUrl`/`列表页`、`detailUrl`/`详情页`、`companyKey`/`公司`、`render`/`渲染`、`notes`/`备注`。所以你可以直接用模板产出的表，也可以自己随手拉一张表。
- 缺 `domain` / `listUrl` 的行会被跳过；表缺列或文件不存在会抛出**明确报错**（提示先跑 `pnpm gen-site:template`）。
- 与 `gen-site` 一样走 `MODEL_MODE`（temp=0），本地模式需先起 Ollama/vLLM（见 04.2.1）。
- 生成完**务必**逐站 `pnpm probe --domain <d>` 验证（见 10.2），再纳入 `crawl` 批次。

> 为什么两条命令而不是一条？模板生成（写 Excel）与批量执行（调模型、落 YAML）**职责不同、触发时机不同**：模板可提前发给同事填，执行往往在填好之后、甚至不同的人来做。拆开后每一步都可单独重跑（`--dry-run` 先看清单）。

## 10.6 backfill · 字段晋升回填

把 `row` JSON 中某字段值回填到已新建的独立列（见 03 §3.9）。

```bash
# 先 dry-run 统计影响行数
pnpm backfill --column clone_number --row-key "Clone Number" --dry
# 确认无误后正式回填
pnpm backfill --column clone_number --row-key "Clone Number"
```

- `--column`：已通过 `db:push` 新建的列名（物理列名，如 `clone_number`）。
- `--row-key`：`row` JSON 中对应的源字段 key。
- `--dry`：只统计、不写库，安全预览。
- 幂等：仅回填目标列为空且 `row` 中确有该 key 的行，可反复跑。

## 10.7 测试站点选择（GFW 友好）

开发与验证阶段优先选用**中国大陆可直连**的站点作为测试对象，避免依赖 VPN：
- 优先用两家竞对清单中位于国内可访问的域名；
- 若必须用海外站点验证，可临时在其 YAML 标 `proxy: required` 并配置代理（见 06.5），或本地先开 VPN 跑 `pnpm probe --domain <x>` 单站验证；
- `gen-site` 同理：给国内可访问的列表页地址，模型生成 + 本地微调更高效。
