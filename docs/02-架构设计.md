## 2.1 端到端流水线

```
Excel 超链接清单（种子，仅初期样本）
   │  pnpm seed（解析 Excel → data/seeds/seeds.json → 增量同步进库）
   ▼
companies / categories ──► ② 爬取范围（真相源）
   │                          · 默认 --source seeds：读库内 categories
   │                          · --source config：扫描 config/sites/*.yaml
   ▼  季度 Scheduler 触发（或手动）
③ Fetch 层（undici/HTTP 优先；静态内容偏少 → Playwright 渲染；限速/UA/代理）
   │   ▲ 代码适配器 preflight 钩子在此注入请求头 / cookie（加性，见 05.3）
   ▼
④ 适配器路由（优先级：配置 YAML → 代码 Adapter 钩子 → 模型通用兜底）
   │   配置 YAML 支持单规则与 sections 多栏目多规则（一域名多套规则，见 05.3.2）
   ▼
⑤ Normalizer（归一化为统一 NormalizedProduct；未声明字段统一进 row）
   │
   ▼
⑥ Diff Engine / 落库（upsert / 同栏目内 dedupeKey 唯一化 / 连续 2 轮缺失才软删）
   │                         │
   ▼                         ▼
⑦ Storage(Drizzle:SQLite→MySQL/PG)   Alert Engine → 邮件/企微/钉钉
   │
   ▼
⑧ Downstream（Excel 导出 / ECharts / Nuxt 应用页）
```

**模型辅助层（贯穿 ③④⑤⑥）**：自适应提取、字段归一化、变化归因、告警摘要，统一经 OpenAI 兼容客户端调用，受严格提示词 + Zod 校验约束 + `temperature=0` + 失败重试（防幻觉四件套，见 04）。模型是**增强不是单点**：失败只降级并落 `MODEL_FAILURE` 告警，不阻塞整轮。

## 2.2 分层职责

| 层 | 职责 | 关键产物 |
|---|---|---|
| 种子源 | Excel → 标准 JSON（`pnpm seed` 解析并增量同步） | `data/seeds/*.json` |
| 爬取范围 | 决定"爬哪些站点/品类/栏目"：`--source seeds`（读库内 categories）或 `--source config`（扫 `config/sites/*.yaml`） | 目标站点 × 栏目清单 |
| Fetch 层 | HTTP(undici) 抓页面；静态内容偏少回退 Playwright；限速/UA/代理；**代码适配器 `preflight` 钩子注入请求头/cookie** | 页面 HTML / JSON |
| 适配器路由 | 按域名路由：**YAML（主力）→ 代码 Adapter 钩子（加性补充）→ 模型通用兜底**；YAML 支持单规则 / sections 多栏目多规则 | 统一产品数据 |
| Normalizer | 异构字段 → 统一 `NormalizedProduct`；其余存 `row` | 结构化产品 |
| Diff / 落库 | 同栏目内 `dedupeKey` 唯一化 → upsert（冲突键 `(company_id, dedupe_key, section_key)`）；连续 2 轮缺失才软删；价格变化记 `price_history` | products / price_history / crawls |
| Storage | Drizzle ORM，SQLite 本地，生产切 MySQL/PG | 数据库 |
| Alert Engine | 分类分级告警，推送指定通道 | 告警事件 |
| Downstream | 导出 / 图表 / 应用页 | 给市场·产品部的交付物 |

## 2.3 设计原则

1. **配置优于代码（加性、不替换）**：简单站点改 `config/sites/*.yaml` 即可，不动代码；YAML 表达不了的环节（过 WAF、自定义分页、解析后补字段）**再加**一个代码 Adapter 文件，只写需要的钩子——YAML 始终是主力与真相源，路由优先级 `YAML → 代码 Adapter → 模型兜底`。**某站点没有适配器文件时，行为与"没有这套机制"完全一致（零回归）**。详见 [05 §5.3](05-站点接入指南.md)。
2. **单一事实源**：DB schema、类型、模型客户端只在 `packages/shared`，crawler 与 web 共用；脚本命令以 [11-脚本命令手册](11-脚本命令手册.md) 为准。
3. **边界归一化**：适配器输出统一结构，下游完全不感知站点差异（见 05）。
4. **无感切换**：DB 方言、模型本地/云端，仅靠环境变量切换（见 03 / 04）；**变量名唯一真相源是 `.env.example`**，有 `envContract.test.ts` 双向校验。
5. **失败可观测（human-in-the-loop）**：凡需人工介入的情况（国外站不可达、翻页接口定位不到）一律**主动告警**，不静默失败（见 07）；单站/单条/单栏目失败只计 `failed` 并继续，不整轮失败。
6. **失败隔离 + 告警自愈闭环**：抓取失败 → 落告警（`NEEDS_API_HINT` 等）→ 人工/规则修订适配器 → 复跑幂等，闭环可追溯（见 07）。

## 2.4 技术选型（详见 ADR）

- 语言/运行时：Node.js + TypeScript（ESM，`tsx` 直跑，无构建产物）
- 抓取：undici/HTTP 优先，Playwright（无头浏览器）+ cheerio（SSR 解析）作为回退
- 模型：本地轻量模型（Ollama/vLLM，如 Qwen2.5-VL）+ 云端大模型兜底（通义 / DeepSeek / Claude），OpenAI 兼容接口
- 存储：Drizzle ORM + better-sqlite3（SQLite → MySQL / PostgreSQL）
- 下游：ExcelJS / ECharts / Nuxt 4
