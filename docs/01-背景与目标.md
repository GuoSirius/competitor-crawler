# 01 · 背景与目标

> 本篇回答"**我们要做什么**"：业务背景、目标、范围、干系人、成功标准。技术实现见后续各篇。

## 1.1 业务背景

市场部 / 产品部需要持续掌握竞品（Abcam、CST、Proteintech、Miltenyi、ATCC、义翘神州等 24 个站点）在**抗体、ELISA、流式、细胞、血清、重组蛋白**等品类上的产品布局与价格动态，用于：

- **竞品对标**：同一品类下各家的产品数量、规格、定价区间对比；
- **动态监控**：季度级产品上下架、价格调整、字段变更（如克隆号、应用说明变化）；
- **决策支撑**：导出给市场 / 产品做汇报、定价参考、选品方向。

现状是人工定期去各官网翻看，效率低、易遗漏、不可追溯。本项目把这个过程**自动化、结构化、可追溯**。

## 1.2 数据来源

| 文件 | 记录数 | 说明 |
|---|---|---|
| `Elabscience竞对清单.xlsx` | 74 条 | 竞对公司多为抗体 / ELISA / 流式等；「竞品品类链接」单元格内嵌真实 URL 超链接 |
| `Procell 竞对清单-2026.9.xlsx` | 32 条 | 细胞 / 细胞试剂 / 血清等；「竞品品类链接」为直接 URL 文本 |

- 合计 **106 条品类记录，覆盖 24 个独立域名**。
- 关键发现：前 74 条并非"无 URL"，而是**文本单元格携带来超链接**（如 Abcam → `https://www.abcam.com/en-us/products/primary-antibodies`）。因此 106 条全部可拿到真实可爬 URL，无需人工补录。
- 提取规则（Seed Loader）：单元格有 `hyperlink` 用 `hyperlink.target`；否则若值是 `http(s)` 开头则直接用。

## 1.3 目标

1. **自动抓取**：定期（季度）爬取 106 个品类页下全部产品详情。
2. **统一存储**：异构页面归一化为统一结构入库，其余原始字段全量兜底存 `raw_row` JSON。
3. **增量维护**：新增产品插入、已有产品更新、下架产品**软删除**（物理不删）。
4. **变更告警**：字段缺失 / 变化 / 批量突变时告警；区分"产品真更新"与"官网改版需改规则"。
5. **可分析交付**：导出 Excel、生成图表、提供应用页，供市场 / 产品部使用。
6. **可演进**：本地 SQLite，后期无感切换 MySQL / PostgreSQL；站点增删改由配置驱动。

## 1.4 范围

**纳入范围**
- 产品字段：产品 id、名称、所属品类、规格+现价+活动价+优惠价（数组）、产品介绍图+对应描述（数组）、克隆号、应用，以及页面其余信息全量存 `raw_row`。
- 列表页形态：分页、滚动加载、搜索页均支持。
- 模型辅助：自适应提取、字段归一化、变化归因、告警摘要。
- 下游：Excel 导出、ECharts 图表、Nuxt 应用页。

**不纳入范围（非目标）**
- 不买卖、不生成内容，仅采集公开产品信息（需遵守 robots / 合规）。
- 不做实时价格预测、销量估算。
- 不做竞品站点的登录后私有数据抓取。
- 第一阶段不追求"每次爬全量实时"，以季度增量为主。

## 1.5 干系人

| 角色 | 职责 |
|---|---|
| 系统开发组（你） | 构建与运维爬虫 / 数据库 / 应用；维护站点接入规则；接收并响应告警 |
| 市场部 / 产品部 | 消费导出、图表、应用页，做对标与决策 |
| 模型（本地/云端） | 辅助提取、归一化、归因、告警摘要（受严格提示词约束） |

## 1.6 成功标准

- 106 个品类可稳定入库，季度增量爬取可重复执行。
- 产品唯一性由 `(company_id, dedupe_key)` 锁定，无重复、不漏更。
- 站点改版时，能在告警指引下通过改配置 / 切模型模式恢复，无需改写核心代码。
- 告警信噪比高：变化归因能区分"真更新"与"规则该改"，不淹没人工。
- 下游交付物可被市场 / 产品部直接用于汇报与决策。
