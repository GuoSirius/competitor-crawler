# 04 · 模型辅助方案

> 本篇回答"**模型用在哪、怎么部署、怎么不让它乱答**"。模型是贯穿 ③提取 / ⑤归一化 / ⑥变化归因 / ⑦告警 四环节的辅助层，经统一客户端调用，受**强提示词 + Zod 校验 + 低温度 + 重试**约束。

## 4.1 业务视角：为什么需要模型

竞品站点的列表页/详情页**千站千面**：字段位置、命名、结构都不一致。若纯靠 XPath/CSS 选择器硬编码，每改一个站就要改代码，且官网一改版就全失效。模型的职责是：

1. **自适配提取**：给模型"这一页的可见内容 + 我要的字段清单"，它输出结构化结果，不用为每个站写解析模板。
2. **字段归一化**：把"克隆号 / Clone / 克隆 / mAb No."统一成 `cloneNumber`，把不同格式的规格价格归一成 `specs[]`。
3. **变化归因**：产品字段变了，模型判断"这是官网真更新"还是"页面结构改版导致提取错位"——直接决定发哪种告警。
4. **告警摘要**：把技术告警翻成市场/产品部能读的"白话"，降低噪声。

> 关键前提（用户要求）：模型**不是替代品**，而是"通用兜底 + 提效"。能稳定用选择器/配置解决的站点优先不调模型；模型在异构/加密/风控页或字段突变时上场。

## 4.2 三种部署模式（纯配置切换）

配置优先级：`.env` 覆盖 `config/model.yaml`；`MODEL_MODE` 决定走哪条路径。

| 模式 | 行为 | 适用场景 |
|---|---|---|
| `local` | 只用本地模型（Ollama/vLLM，OpenAI 兼容） | 内网 / 无外网 / 数据不出本机 / 成本敏感 |
| `cloud` | 只用云端大模型（通义 / DeepSeek / Claude） | 本机无 GPU / 追求最强理解力 |
| `hybrid`（默认） | **本地优先**，本地失败/超时/不可用自动回退云端 | 兼顾隐私与可用性，日常推荐 |

`.env.example`：
```env
MODEL_MODE=hybrid
MODEL_LOCAL_BASE_URL=http://localhost:11434/v1
MODEL_LOCAL_API_KEY=ollama
MODEL_LOCAL_MODEL=qwen2.5:14b-instruct
MODEL_CLOUD_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_CLOUD_API_KEY=
MODEL_CLOUD_MODEL=qwen-max
MODEL_TEMPERATURE=0
MODEL_MAX_RETRIES=1
```

`config/model.yaml` 与之等价，且支持**按任务覆写温度**：
```yaml
mode: hybrid
tasks:
  extraction:   { temperature: 0 }   # 提取必须确定性
  normalization:{ temperature: 0 }
  attribution:  { temperature: 0 }
  summary:      { temperature: 0.3 } # 摘要可略宽容
```

### 4.2.1 本地模型选型建议

| 任务 | 推荐模型 | 说明 |
|---|---|---|
| 文本提取 / 归一化 | `qwen2.5:14b-instruct` | 中文强、指令遵循好、14B 在消费级 GPU 可跑 |
| 视觉页提取（JS 渲染 / 加密 / 风控站） | `qwen2.5-vl:7b` | 直接读"用户所见截图"，绕开逆向 |
| 轻量兜底 | `qwen2.5:7b` | 低资源环境 |

> 视觉模型是用户"优先用浏览器渲染内容、不逆向接口"要求的天然搭档：Playwright 截图 → 多模态模型读图提取，完全在 UI 层获取数据，最难被识别/封禁。

## 4.3 防幻觉四件套（必须全部满足）

1. **强约束提示词**：明确"只输出规定字段，缺失字段填 `null`，禁止编造，禁止输出字段外内容"。
2. **Zod 校验**：模型输出先过 Zod schema，结构/类型不符直接判失败。
3. **temperature = 0**：关闭随机性，同输入同输出，结果可复现、可审计。
4. **失败重试一次**：校验失败或超时，按 `MODEL_MAX_RETRIES=1` 重试一次；仍失败则降级（selector 兜底 / 标记 `MISSING_FIELD` 告警），**绝不拿半成品入库**。

### 4.3.1 统一请求封装（伪代码）

```ts
async function callModel<T>(task: Task, prompt: string, schema: ZodSchema<T>): Promise<T> {
  const cfg = resolveConfig(task);            // 取 mode + 任务覆写温度
  const client = pickClient(cfg.mode);        // local | cloud | hybrid(带回退)
  const resp = await client.chat({
    model: cfg.model,
    temperature: cfg.temperature,             // 默认 0
    messages: [systemPrompt(task), user(prompt)],
  });
  const parsed = safeJsonParse(resp);
  const result = schema.safeParse(parsed);    // Zod 校验
  if (!result.success) {
    if (retriesLeft-- > 0) return callModel(task, prompt, schema); // 重试一次
    throw new ModelValidationError(task, resp); // 上层转告警，不入库脏数据
  }
  return result.data;
}
```

## 4.4 各环节的提示词契约（要点）

> 完整 prompt 模板放 `config/prompts/*.md`，由代码注入变量；这里只列**约束红线**，防止模型不一致或臆造。

### 4.4.1 提取（extraction）
- 输入：页面可见文本 + 截图（可选）+ 目标字段表。
- 契约：`specs` 必须是数组，每项含 `spec/priceNow/priceActivity/pricePromo`；`introMedia` 每项含 `image/description`；页面没有的字段一律 `null`。
- 红线：**不得根据常识补全价格/克隆号；不得为凑数编造数组项**。

### 4.4.2 归一化（normalization）
- 输入：上一步提取结果 + 字段同义词表。
- 契约：输出统一 `NormalizedProduct`；不同语言的同一概念映射到同一字段名。
- 红线：不改变语义；无法确定的映射保持原值进 `row`。

### 4.4.3 变化归因（attribution）
- 输入：旧 `row` vs 新 `row` 的差异字段。
- 输出：`{ kind: 'real_update' | 'structural_change' | 'extraction_error', confidence, reason }`。
- 红线：低置信度时归为 `extraction_error` 并触发"规则待复核"告警，而非武断判定。

### 4.4.4 告警摘要（summary）
- 输入：结构化告警列表。
- 输出：给市场/产品部的人话摘要（中文，分"发生了什么/影响/建议动作"）。
- 红线：不替人工做决策，只陈述事实与建议。

## 4.5 成本与可观测

- 每个模型调用都带 `task` 标签，记录到本次 `crawls.summary`（调用次数、失败数、回退次数）。
- `hybrid` 模式下本地优先可显著降本；云端仅作兜底，异常高调用量本身也是"本地挂了"的告警信号。
- 温度、重试、模型名全部配置化，**加新模型/换厂商不碰代码**，只改 `config/model.yaml` / `.env`。

## 4.6 失败链路总览

```
模型不可用（本地挂 + 云端也挂 / 无网）
   → 该站点降级为"selector 兜底"（若有配置）或跳过
   → 发 SITE_UNREACHABLE / 提取失败告警
   → 该站点本轮标记 partial，不影响其他站点
```

> 模型是**增强**不是**单点**：任一层模型失败都应有降级路径，绝不因此阻塞整轮爬取（见 07 告警分级）。
