# 11 · 脚本命令手册（统一维护，单一真相源）

> 本文件是**全部可执行脚本的唯一真相源（single source of truth）**。新增 / 修改任何脚本，必须同步更新本文件，并在**根 `package.json`** 保留对应入口（避免频繁切换工作目录）。每条脚本标注：所在包、作用、用法、适用场景。

## 11.1 约定

- **根优先**：所有脚本在根 `package.json` 都有入口，统一 `pnpm <script>` 触发，不必 `cd` 进子包。
- **子包兜底**：各子包 `package.json` 保留自身实现（便于单独调试），但根必须镜像。
- **命名**：子包同名脚本根直接复用同名；web 的 `dev` / `build` 在根为 `dev:web` / `build:web`（避免与根潜在冲突）。
- **登记**：新增脚本 → 子包加实现 → 根加入口 → 本文件 §11.x 补一行。

## 11.2 种子与数据

- 包：crawler（根同名 `pnpm seed`）
- 作用：读 Excel 种子 → 抽取 `data/seeds/seeds.json` → 增量同步 `companies` / `categories` 进库
- 用法：`pnpm seed`
- 场景：竞品清单 Excel 更新后

## 11.3 数据库

### `db:push`
- 包：shared（`pnpm --filter @competitor-crawler/shared db:push`）
- 根入口：`pnpm db:push`
- 作用：drizzle-kit push，按 `packages/shared/src/db/schema.ts` 同步表结构 / 索引（**唯一迁移入口**，绝不散写 SQL）
- 用法：`pnpm db:push`
- 场景：改 schema 后（含新增列、索引变更）

## 11.4 抓取与站点接入

### `crawl`
- 包：crawler（根同名 `pnpm crawl`）
- 作用：全量增量爬取。流程：按数据源确定站点范围 → 逐站点 `sections` 选栏目 → 列表翻页（给条目打 `sectionKey`）→ 详情解析归一化 → upsert（冲突键 `(company_id, dedupe_key, section_key)`，去重口径 B）→ 软删（连续 2 轮缺失才 `delisted`）；每轮记 `crawls` 批次
- 爬取范围数据源（需求①·决策B，可切换）：
  - `--source seeds`（**默认**，旧行为稳定）：沿用库内 `categories`（种子 Excel 入库）作为范围
  - `--source config`：扫描 `config/sites/*.yaml` 作为真相源，自动按 YAML 的 `company` 字段（缺省回退域名）upsert 公司、按 `sections[].category` + `sections[].productLine` upsert 品类进库——种子 Excel 仅作初期样本，非后期爬取依据（`--dry-run` 下改为仅预览：不新建/更新公司品类，只打印「将新建/将更新」日志）
- YAML ↔ 代码适配器互斥（决策A）：某站点同时有 `config/sites/<domain>.yaml` 与 `packages/crawler/src/adapters/<domain>.ts` → 记冲突、跳过该站点、跑完所有站点后**汇总提示待用户处理**（不中断整轮）
- 用法：
  - `pnpm crawl` 全量（默认 seeds 源）
  - `pnpm crawl --source config` 改用 config 目录作为范围（后期驱动）
  - `pnpm crawl --site <domain>` 仅爬指定站点（调试 / 单站补跑）
  - `pnpm crawl --section <key>` 仅爬指定栏目（逗号分隔多个；多规则站点用 `sections[].key`）
  - `pnpm crawl --category <名>` 仅爬品类名子串命中的栏目（不区分大小写）
  - `pnpm crawl --product-line <线>` 仅爬指定产品线（`seeds` 模式按 categories.product_line 过滤；`config` 模式按 YAML `sections[].productLine` 过滤，未声明产品线的栏目排除）
  - `pnpm crawl --dry-run --pages 2 --limit 5` 只爬前 2 页、每栏目最多 5 条详情、**完全不写库**（接站点前验证）：不插 `crawls` 运行记录、产品不 upsert、`--source config` 的公司/品类 upsert 也降级为仅预览（打印「将新建/将更新」），全程零写入
  - `pnpm crawl --render ssr|spa|auto` 指定渲染模式（默认 auto：静态内容偏少自动回退 Playwright）
- 场景：季度主任务
- 失败隔离：单站 / 单条 / 单栏目抓取失败只计 `failed` 并继续，不整轮失败

### `probe`
- 包：crawler（根同名 `pnpm probe`）
- 作用：单站验证，抽测 YAML 适配器解析是否正确（先验证再批量）；并**抽查详情页自动判定「规格×价格形态」**（docs/05 §5.3.4）
- 用法：`pnpm probe --domain <domain> [--list-url <url>] [--section <key>] [--render auto|ssr|spa] [--sample 5] [--detail 1]`
- 必填：`--domain`（对应 `config/sites/<domain>.yaml`）；`--list-url` 缺省时取栏目的 `startUrls` / YAML `startUrl`
- `--section`：多规则站点只验证指定栏目（`sections[].key`）；省略则遍历全部栏目
- `--detail`：每栏目抽查几个详情页做形态探测（默认 1；`--detail 0` 关闭）
- 形态探测行为：
  - A/B/C → 打印「静态可抽」+ **可直接粘贴的 YAML 片段**
  - D/E → 打印**「在哪配、怎么配」的完整步骤**，并写入 `alerts`（`type=NEEDS_API_HINT`，幂等不重复）
  - 已配 `parseDetail.api` → 跳过形态提示，**实测接口**并打印「取到 N 条」+ 首条样本
- 场景：新增 / 改站点前（多规则站点逐栏目验证）
- 详见：[10-验证与配置生成工具](10-验证与配置生成工具.md#102-probe--单站验证)、[05-站点接入指南 §5.3.4](05-站点接入指南.md)

### `gen-site`
- 包：crawler（根同名 `pnpm gen-site`）
- 作用：模型驱动生成站点 YAML 配置（抓取页面 → 调模型 temp=0 → 产出 `config/sites/<domain>.yaml`）
- 用法：`pnpm gen-site --domain <d> --list-url <u> [--detail-url <u>] [--company-key <k>] [--render auto] [--notes "..."]`
- 必填：`--domain`、`--list-url`
- 场景：新增站点；产出后 `pnpm probe` 验证
- 备注：`--company-key` 会写入产出 YAML 的 `company` 字段，作为 `crawl --source config`（默认）下归属公司名（缺省按域名兜底）
- 详见：[10-验证与配置生成工具](10-验证与配置生成工具.md#103-gen-site--模型驱动生成配置)

### `gen-site:template`
- 包：crawler（根 `pnpm gen-site:template`）
- 作用：生成「批量站点配置」Excel 模板（含表头 + 示例行 + 填写说明页），默认落 `data/seeds/gen-site-template.xlsx`
- 用法：
  - `pnpm gen-site:template`（默认路径）
  - `pnpm gen-site:template --file <路径>`（自定义输出）
- 场景：有**一批**站点要生成配置时，先生成模板、填好后用 `gen-site:batch` 一次性批量生成（替代逐个 `gen-site`）
- 列：`域名(domain)` / `列表页URL(listUrl)`（必填）、`详情页URL(detailUrl)` / `公司(companyKey)` / `渲染(render)` / `备注(notes)`（可选）

### `gen-site:batch`
- 包：crawler（根 `pnpm gen-site:batch`）
- 作用：读取批量表 → 逐行调用 `genSite`（模型驱动）生成 `config/sites/<domain>.yaml`；**失败隔离**（单行失败只计失败并继续）
- 用法：
  - `pnpm gen-site:batch`（默认读 `data/seeds/gen-site-batch.xlsx`）
  - `pnpm gen-site:batch --file <路径>`（指定其它 Excel）
  - `pnpm gen-site:batch --dry-run`（仅解析并打印待生成清单，不调模型、不落盘）
- 场景：批量新增站点；先用 `gen-site:template` 填表，再本命令一次性生成
- 列识别按表头关键字（domain/域名、listUrl/列表页、detailUrl/详情页、companyKey/公司、render/渲染、notes/备注），大小写不敏感

### `backfill`
- 包：crawler（根同名 `pnpm backfill`）
- 作用：字段晋升回填（把 `row` JSON 中某字段值回填到已新建的独立列）
- 用法：`pnpm backfill --column <col> --row-key <key> [--dry]`
- 场景：后期把重要字段晋升为独立列后，回填历史数据（幂等，可反复跑）
- 详见：[10-验证与配置生成工具](10-验证与配置生成工具.md#104-backfill--字段晋升回填) 与 [03-数据库设计 §3.9](03-数据库设计.md)

## 11.5 下游与前端

### `report`
- 包：crawler（根同名 `pnpm report`）
- 作用：生成下游交付物（Excel 导出 / 图表）
- 用法：
  - `pnpm report`（等同 `--excel`，默认）→ `data/exports/<季度>-竞品对标.xlsx`，含三张表：**总览**（公司 × 品类 产品数矩阵）/ **价格清单**（specs 展开为多行）/ **字段覆盖**（各公司货号/价格/克隆号… 覆盖率）
  - `pnpm report --company 逍鹏 --category 完全培养基` → 按公司 / 品类筛选（子串、不区分大小写），文件名自动加后缀
  - `pnpm report --out <dir|file>` → 自定义输出目录 / 文件名前缀
  - `pnpm report --charts` → `data/exports/<季度>-竞品对标.html`（**自包含** HTML，ECharts 走 CDN），含 6 张图：公司产品总数 / 公司×品类 / 品类占比 / 价格分布 / 克隆号覆盖 / 入库趋势（按 `first_seen_at`）
  - `--excel --charts` 可同时给出（成对输出同名前缀的 `.xlsx` / `.html`）
- 只读活跃产品（`status='active'`）；输出目录 `data/exports/` 已在 `.gitignore` 中忽略
- ⚠️ 价格类图基于**当前快照**，不消费 `price_history`（该表只写不读，见 docs/08 §8.4）
- 场景：季度爬取完成后交付市场 / 产品部

### `dev:web` / `build:web`
- 包：web（子包 `dev` / `build`）
- 根入口：`pnpm dev:web` / `pnpm build:web`
- 作用：前端开发服务器 / 生产构建

## 11.6 环境与质量

### `playwright:install`
- 包：crawler（封装）
- 根入口：`pnpm playwright:install`
- 作用：安装 Playwright 浏览器内核（root 下 playwright 无二进制，故委托 crawler 包执行）
- 用法：`pnpm playwright:install`
- 场景：首次安装 / 升级 Playwright 后

### `typecheck`
- 包：全仓（`node scripts/typecheck.mjs`，依次 shared → crawler → web）
- 根入口：`pnpm typecheck`（**唯一入口**，自动纳管 web）；`pnpm typecheck:web`（仅 web，等价 `nuxt typecheck`）；`pnpm typecheck:all`（与 `pnpm typecheck` 同义）
- 作用：TypeScript 类型检查
- 场景：CI 与提交前（依赖安装后）
- **web 门禁自适应**：脚本检测 `packages/web/node_modules/vue-tsc` 是否存在——
  - 未安装（还没 `pnpm install`）→ 提示跳过，只校验 shared + crawler，门禁**不会变红**；
  - 已安装 → 自动跑 `nuxt typecheck`（内部先生成 `.nuxt/` 类型）。
  所以给 web 加依赖后**只需 `pnpm install`**，无需改脚本 / CI。详见 [12-工程规范 §12.9](12-工程规范.md)。
- ⚠️ 往 `packages/web/package.json` 增删依赖后，`pnpm-lock.yaml` 必须同步更新并提交，否则 CI 的 `--frozen-lockfile` 会失败。

### `test`
- 包：根
- 作用：跑单元测试（vitest，68 例：抽取层 FieldSpec / 形态探测 / 配置归一化 / URL 去重 / 模型配置解析 / **环境变量契约**）
- 用法：`pnpm test`（单次，CI 用）；`pnpm test:watch`（开发时监听）
- 用例位置：**与源码同目录**（`packages/*/src/**/*.test.ts`），见 [12-工程规范 §12.10](12-工程规范.md)
- ⚠️ `envContract.test.ts` 会校验「`process.env` 读取点 ↔ `.env.example` 声明」双向一致，**写错变量名会直接失败**（见 [12-工程规范 §12.13](12-工程规范.md)）
- 场景：提交前门禁、CI

### `hooks:install`
- 包：根（脚本 `scripts/install-hooks.mjs`）
- 作用：安装**回退版**git 钩子到 `.git/cph/`（幂等）。首选是 husky（`pnpm install` 时由 `prepare` 自动启用）；此回退用于 husky 包装脚本在本机 PATH 下不可用时
- 用法：`pnpm hooks:install`，之后用 `git -c core.hooksPath=.git/cph commit -m "feat: ..."`
- ⚠️ 两条路径**门禁强度完全相同**（都调用同一份 `scripts/precommit.mjs` / `scripts/commitmsg.mjs`），不存在「换 hooksPath 就绕过」
- 场景：换电脑 / 钩子丢失后重建

### `commitlint`
- 包：根
- 作用：校验提交信息符合 Conventional Commits；提交时由 **pre-commit/commit-msg 钩子**自动跑（husky 或 `.git/cph`）
- 用法：`pnpm commitlint --from=HEAD~1`
- ⚠️ 两条硬约束（踩过）：`type` 必须是标准枚举（无 `config`，用 `chore`）；**主题不能以大写单词开头**（`FieldSpec 支持…` 会被 `subject-case` 拒绝）
- 场景：提交前自查 / CI 校验

## 11.7 版本与 Changelog

### `release`
- 包：根（脚本 `scripts/release.mjs`）
- 作用：standard-version 自动 bump 版本 + 写 `CHANGELOG.md` + 打 `vX.Y.Z` 标签并提交
- 用法（**只此一个脚本**，运行时选择类型）：
  - `pnpm release` → 交互式询问 patch / minor / major
  - `pnpm release major` → 直接指定类型（非交互，便于 CI / 一键；当前 0.1.0 → 切 1.0.0）
- 场景：发布版本（打标签后由你手动 `git push --follow-tags`）

### `changelog`
- 包：根
- 作用：仅依据提交历史重新生成 `CHANGELOG.md`（不提交、不打标签）
- 用法：`pnpm changelog`
