# 09 · 切换生产库

> 本篇回答"**本地 SQLite 跑得好好的，后期怎么无缝换成 MySQL / PostgreSQL**"。核心：业务代码零改动，只换方言与连接串。

## 9.1 业务视角：为什么要能切

- 本地 SQLite 适合单人季度跑、十万级数据，零运维。
- 后期若多人协作、应用页高并发读、数据量增长，需 MySQL / PostgreSQL 的生产级能力。
- 目标：**切换时爬虫代码、下游代码一行都不用改**，只改配置。

## 9.2 无感切换机制（Drizzle）

Drizzle ORM 把"表定义"与"方言驱动"解耦：

```ts
// packages/shared/src/db/dialect.ts
import { drizzle } from 'drizzle-orm/better-sqlite3'; // sqlite
// import { drizzle } from 'drizzle-orm/mysql2';      // mysql
// import { drizzle } from 'drizzle-orm/node-postgres';// pg

export function createDb() {
  switch (process.env.DB_DIALECT) {
    case 'mysql':  return drizzle(mysqlClient, { schema });
    case 'postgresql': return drizzle(pgClient, { schema });
    default:       return drizzle(sqliteClient, { schema });
  }
}
```

- `schema`（`packages/shared/src/db/schema.ts`）用 Drizzle 跨方言类型定义，**同一份**供三方言复用。
- 切换步骤：
  1. `.env`：`DB_DIALECT=mysql`（或 postgresql），`DATABASE_URL=...`。
  2. `pnpm --filter @crawler/db db:push`（按目标方言建表/迁移）。
  3. 历史数据迁移（见 9.3）。
  4. 重启 crawl / web，业务代码不变。

## 9.3 历史数据迁移

- SQLite → MySQL/PG 的数据搬运用一次性脚本（`scripts/migrate-sqlite-to-sql`），逐表 `SELECT` 旧库 → `INSERT` 新库，保留 `created_at/updated_at/status` 等。
- JSON 列映射：SQLite 存文本 JSON，MySQL 用 `JSON` 类型、PG 用 `jsonb`（Drizzle 自动处理序列化）。
- 软删除数据（status='delisted'）一并迁移，保证历史完整。

## 9.4 类型映射注意点

| 概念 | SQLite | MySQL | PostgreSQL |
|---|---|---|---|
| 自增主键 | `integer PK autoincrement` | `int AUTO_INCREMENT` | `serial` / `identity` |
| JSON | `text`（应用层解析） | `json` | `jsonb`（可 GIN 索引） |
| 唯一索引 | `CREATE UNIQUE INDEX` | 同 | 同（组合唯一索引跨方言一致） |
| 时间戳 | `integer`（Unix 秒） | `int` / `datetime` | `int` / `timestamptz` |

- 设计阶段已统一用 **Unix 秒整数**存时间，规避各库 datetime 时区差异。
- 组合唯一索引 `(company_id, dedupe_key)` 三方言语义一致，迁移无歧义。

## 9.5 进阶：多品类从属（可选扩展）

若业务需要"同一产品归属多个品类"（而非 03.4 的"最近归属"），引入关联表：

```ts
export const productCategories = sqliteTable('product_categories', {
  productId: integer('product_id').references(() => products.id),
  categoryId: integer('category_id').references(() => categories.id),
}, (t) => ({ pk: primaryKey(t.productId, t.categoryId) }));
```

- 这是**向后兼容扩展**：不破坏现有组合唯一索引，新增关联表即可支持多从属查询。

## 9.6 切换检查清单

```
[ ] 目标库实例已建、账号/白名单就绪
[ ] .env 改 DB_DIALECT + DATABASE_URL
[ ] db:push 成功（表结构一致）
[ ] 历史数据迁移脚本跑通，行数对账一致
[ ] 跑一次 dry-run crawl 验证读写
[ ] 下游 report / Nuxt 应用页验证可读
[ ] 告警通道正常（切换不丢告警）
```

> 切换本身只在 `packages/shared` 与 `.env` 层面，符合"无感"目标；任何站点适配器、模型配置、调度逻辑均不受影响。
